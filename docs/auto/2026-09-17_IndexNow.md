# IndexNow（更新を検索エンジンに知らせる仕組み）

入れた日: 2026-09-17 / 入れた人: 司令室B（自動実行）

## これは何か

ふつうは「検索エンジンが見に来てくれるのを待つ」。IndexNow はその逆で、
**更新したURLをこちらから知らせる**仕組み。無料・アカウント不要・固定費なし。

- 対応しているのは **Bing / DuckDuckGo など**。**Google は対応していない**
- したがって North Star（Google 検索からのクリック数）は直接は動かない。
  Bing 系からの流入が早くなる分だけの効き目、と見ておく
- 入れるのは1回きりで、あとは自動。だから「効き目は中くらいだが、やる価値はある」と判断した
  （調べた結果は `docs/auto/2026-09-17_稼働ゼロの集客_調べた結果.md` の2番）

## 仕組み（3つだけ）

| もの | 場所 | 中身 |
|---|---|---|
| 鍵 | `lib/indexnow.ts` の `INDEXNOW_KEY` | 32文字の文字列。**秘密ではない**（公開前提の仕組み） |
| 鍵のファイル | `public/<鍵>.txt` | 中身は鍵と同じ文字列。「このサイトの持ち主が送っている」ことの証明 |
| 送る処理 | `scripts/indexnow.ts` | 送るURLを決めて POST するだけ |

**鍵を変えるときは、`lib/indexnow.ts` の文字列と `public/` のファイル名・中身を必ず一緒に変える。**
片方だけ変えると送信が弾かれる。

## いつ送られるか

ビルドのあと（`postbuild`）に自動で走る。ただし **Vercel の本番ビルドのときだけ**
（`VERCEL_ENV=production`）。プレビューや手元のビルドでは何も送らない。

送るURLは **直前のコミットで中身が変わったスポット**の詳細ページ（日英韓）＋ 一覧側のページ。
変わったスポットが無ければ **何も送らない**。同じURLを毎回送り続けても意味が無いため。
（`.git` が読めない所では「直近7日以内に出典を確認し直したスポット」で代用する）

**この処理でビルドは失敗しない。** 送信に失敗しても記録を出して正常終了する。
検索エンジンへの通知が遅れることより、サイトが出ないことのほうが困るため。

## 手で動かすとき

```
npm run indexnow -- --dry-run   # 送らずに、送る予定のURLを数えるだけ
npm run indexnow -- --all       # 全URLを送る（最初の1回・作り直したときだけ）
```

初回の全送信は `tasks/queue/2026-09-22_STEP21_indexnow-first.txt` に置いてある
（本番に鍵のファイルが出ているかを確かめてから送る作り）。
