確認は原則スキップして進めてよい。ただし以下は絶対に実行せず、必要になったら先に私に確認すること。
(1) 全データの削除や取り返しのつかない操作（git push --force、rm -rf、条件なしの一括削除など）
(2) 課金や支払いが発生する操作
(3) 出典の無いスポットを載せること。出典に無い項目（料金・営業時間・定休日・特徴）を推測で書くこと。事業者への連絡。既存の listing JSON の削除・書き換え。

【前提】
CLAUDE.md、docs/要件.md を最初に読むこと。今回は WebFetch と curl が許可されている（.claude/settings.local.json）。最初に1件だけ WebFetch で下の「探す場所」を開いて、ネットが通ることを確かめてから始めること。通らなければ「ネット不可」と RESULT に書いて何も変えずに終える。
作業前に git fetch && git pull origin main をすること（ローカルが古いと重複を見落とす）。
今回は **食（data/listings/food）の「焼酎蔵（shochu）」と「直売所（market）」だけ** を対象にする。地鶏（jidori）・農園体験（farm）は今回やらない。いまの件数：焼酎蔵22・直売所37。宮崎県酒造組合には焼酎蔵が30以上あるので、焼酎蔵は特に抜けが多い。

【追加の決まり（全ジャンル共通）】
- 1件ずつ `npx tsx scripts/add-listing.ts <genre> <slug> <出典URL>` で雛形を作り、出典を WebFetch で読んで項目を埋める。手書きで JSON を新規作成しない
- 出典は「その施設の公式サイト」を最優先。公式サイトが無い施設は、自治体・観光協会・業界団体の公開ページ（下の「探す場所」に挙げたもの）を出典にしてよい。個人ブログ・口コミサイト・SNS だけが出典の施設は追加しない
- 埋めるのは出典に書いてある項目だけ。無い項目は null のまま（hours / price / phone / website / google_maps_url）。price の書き方は CLAUDE.md の price の行に従う（「約」「目安」は使わない）
- description は日本語1〜2文の事実だけ（規模・場所・設備）。評価語（絶景・人気・おすすめ・最高）は書かない。en は ja の訳。英語だけにある情報を作らない
- category と area は data/taxonomy.json にあるものだけ。features は出典で確認できるものだけ（主観の特徴は付けない）。新しい genre / category / feature を足したくなったら足さずに RESULT に書いて止まる
- slug は小文字とハイフンのみ。既存と重複しないこと
- **重複チェックを必ずする**：追加前に `grep -ril "<施設名の主要部分>" data/listings/` で既存の listing（名前の表記ゆれ・同じ住所・同じ電話番号）を探し、あれば追加しない。同じ敷地でも役割と連絡先が別なら別 listing でよい（CLAUDE.md）
- 閉業・休業が出典で分かる施設は追加しない
- 1件の出典取得に失敗しても止まらず次へ。同じURLの再試行は1回まで
- 時間の上限：この1回で追加するのは **最大25件**。25件に達したら、残りの候補（名前と出典URL）を tasks/queue/候補_<genre>_残り.md に書いて止める（次回の順番待ちで続きをやる）
- 全部終わったら npm run validate → npm run build → 通ったらコミット → git push origin main。ビルドが通らなければ push せず、変更はそのまま残して RESULT に書く

【禁止】
- 出典の無い施設・項目の追加、推測・概算・口コミからの転記
- 既存 listing JSON の書き換え・削除（今回は新規追加だけ）
- ページ・デザインのコード変更、他ジャンルの JSON 変更、taxonomy.json の変更

【RESULT 行に含めること】
<genre>：追加した件数／重複で見送った件数／出典不足で見送った件数／残り候補の件数／push YES|NO／コミットハッシュ。追加した slug の一覧をログ本文に書く。
