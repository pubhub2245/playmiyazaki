【安全ルール】
確認は原則スキップして進めてよい。ただし以下は絶対に実行せず、必要になったら先に私に確認すること。
(1) 全データの削除や取り返しのつかない操作（git push --force、rm -rf、条件なしの一括削除など）
(2) 課金や支払いが発生する操作
(3) 出典に無い料金を書くこと。推測・概算・口コミからの転記。事業者への連絡。listing JSON の削除。

【前提】
CLAUDE.md、docs/要件.md を最初に読むこと。今回は WebFetch と curl が許可されている（.claude/settings.local.json）。最初に1件だけ WebFetch で出典を開いて、ネットが通ることを確かめてから始めること。通らなければ「ネット不可」と RESULT に書いて何も変えずに終える。
今回は **サーフィン（data/listings/surf）だけ** を対象にする。他ジャンルは触らない。

【やること】STEP 14-3：サーフィンの料金の拾い直し（データのみ）
1. data/listings/surf/*.json のうち price が null のものを1件ずつ、sources のURLを WebFetch で開き、料金が書いてあれば price.ja / price.en を埋める。書き方は CLAUDE.md の price の行に従う（出典の金額をそのまま短く1〜2行。税込／税別は出典どおり。「約」「目安」は使わない）
   - 出典に料金が無くても、同じ公式サイト内の「料金」「ご利用案内」「プラン」ページにあることが多い。その場合はそのURLを sources に追加して price を埋める（sources への追記は許可）
   - 料金ページが無い／PDFで読めない／前年度以前の料金しか無い → null のまま
   - price を書き換えた listing は verified_at を今日の日付に更新
   - 出典を開いたついでに、閉業・移転が分かった listing は status を "closed" にする（削除はしない）。それ以外の項目は触らない
   - 1件の出典取得に失敗しても止まらず次へ。同じURLの再試行は1回まで
2. npm run validate → npm run build → 通ったらコミット「Backfill surf prices from sources (STEP 14-3)」→ git push origin main。ビルドが通らなければ push せず、変更はそのまま残して RESULT に書く

【禁止】
- 出典に無い金額（概算・推測・口コミ転記）
- 料金・verified_at・sources 追記・status 以外の項目の書き換え
- ページ・デザインのコード変更、他ジャンルの JSON 変更

【RESULT 行に含めること】
surf：price を埋めた件数／null のままの件数／closed にした件数／push YES|NO／コミットハッシュ。null のまま残った施設の slug 一覧は tasks/done に移される前提で、ログ本文にも書く。
